## 1. 范围

- 收敛核心规范的唯一职责，删除跨文件规则副本和模型常识解释。
- 压缩 README、SPEC/TASK/RUNBOOK 模板及 walkthrough，使其只承担导航、字段或示例职责。
- 修正 TASK 更新、阻塞缺口、风险接受、工具无关和凭据存储的语义冲突。
- 明确历史任务按需读取，不移动或改写既有历史正文。

非目标：不修改产品源码、CI/CD、既有任务证据和旧 CHANGELOG 条目；不推送、不合并、不发布。

## 2. 验收例子

1. 文件权威、分档、设计验证、完成状态和部署边界各有一个详细正文，其他位置只保留短引用。
2. 模板不再把未决的 SPEC 拆分方案写成规则，也不复制治理政策。
3. walkthrough 只陈述具体场景、选择和结果，不形成第二套规范。
4. 外部写授权、未知结果停止、部署防绕过、敏感信息、E2E、首次推送和 worktree 清理边界仍可定位。
5. Markdown 引用有效，`git diff --check` 通过，既有历史任务内容不变。

## 3. 计划与风险

- 设计依据：单一权威正文原则及用户批准的 A～E 审查建议。
- 采用路径修正：通用文件权威和部署规则放在可复制的 `AGENTS.md` 第 1.1、3.1 节；产品 SPEC 记录具体设计。避免替换产品 SPEC 模板后引用失效。
- 技能：本次用户明确选择不启用 ponytail。
- 步骤：核心规则收敛 → 模板与示例压缩 → 基线记录 → 链接和语义验证 → 本地提交。
- 拆分：单任务；各文档共享同一权威关系，分开交付会产生暂时冲突。
- 并行：串行；核心文件和引用目标高度重叠。
- 风险：过度压缩可能削弱安全边界；通过必保语义搜索和逐项对照控制。
- 补充审查：采用奥卡姆剃刀，只删除重复解释，不删除改变授权、状态或证据判定的条件。
