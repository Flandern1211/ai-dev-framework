# AI 开发通用规范

一套与具体产品、具体 AI 工具无关的 AI 开发规范。默认轻，按风险升级；把成本放在可执行验证上，而不是为每个任务维护完整文档。

## 1. 文件

| 文件 | 作用 |
| --- | --- |
| `AGENTS.md` | 共同入口：授权、安全、工作区、Git 边界，以及默认执行流程。 |
| `SPEC.md` | 当前基线：范围、需求与 AC、架构边界、对外契约、数据模型。 |
| `CHANGELOG.md` | 基线变更记录。 |
| `TASK.md` | 任务状态、档位和证据位置；完整档任务在 `tasks/`。 |
| `project-conventions.md` | 构建、测试、凭据、Git 分支、提交和首次推送细则。 |
| `templates/` | SPEC 和完整档任务骨架。 |
| `examples/walkthrough.md` | 轻档和完整档的纸面示例。 |
| `scripts/` | 可选：提交信息安全检查钩子。 |

## 2. 拆分与分档

- **拆分**：对齐后按独立结果/契约、失败/回滚边界、中间态可交付、共享契约四问判断；多个可独立交付、独立验收的能力默认拆成多个任务，分别登记依赖、分档和验收。跨模块或预计超过半天只决定档位，不作为合并任务的理由。
- **轻档（默认）**：不涉及外部写、权限/身份、数据迁移、对外契约、跨模块或半天以上、跨会话/跨 agent 交接。产物是代码、测试、一条提交和 `TASK.md` 一行。
- **完整档**：命中任一条件。另有约 30～50 行任务文件，包含范围、验收例子、计划与风险、证据摘要。

每个任务开工时判断档位，并在 `TASK.md` 记一行理由。拆出的任务按关系决定串行或并行：无依赖、触碰范围不重叠且无共享未合入契约时默认并行，存在依赖或重叠时串行，判定见 `project-conventions.md` 第 6.9 节。

## 3. 质量门

1. **对齐门**：3～5 条可判定验收例子；剩余问题不再改变实现方向和验收结果时停止追问。
2. **拆分门**：对齐后按能力边界判断任务粒度；多个可独立交付的能力默认拆分并登记依赖。
3. **计划门**（完整档）：对抗性审查 + 奥卡姆检查。
4. **交付门**：可执行验证，记录命令、结果和 🔴 未测试/未验收表（无则写「🔴 无」）。

## 4. 采用

1. 复制五个文件到产品仓库根目录：`AGENTS.md`、`SPEC.md`、`CHANGELOG.md`、`TASK.md`、`project-conventions.md`。
2. 用 `templates/SPEC.md` 建立基线，填写构建、测试、凭据和发布流程。
3. 新任务先按能力边界拆分，再逐个判断档位；默认轻档，命中完整档条件再建立任务文件。
4. 其他 AI 工具入口文件引用 `AGENTS.md`，不复制另一套规则。
5. 可选：安装 `scripts/check-commit-msg.sh` 为 `commit-msg` 钩子，拦截常见凭据和个人信息模式。

## 5. 权威关系

`AGENTS.md` 管操作边界和流程；`SPEC.md` 管当前基线；`CHANGELOG.md` 管基线变更；`TASK.md` 管任务状态和证据位置；`project-conventions.md` 管工程细则。README 和 `examples/` 不是权威正文。

## 6. 维护

1. 规则变化更新对应文件，并在 `CHANGELOG.md` 记录重要变化。
2. 基线变化更新 `SPEC.md` 和 `CHANGELOG.md`；任务级调整不上升为基线。
3. 同一主题只保留一个权威正文；其他文件引用，不复制。
