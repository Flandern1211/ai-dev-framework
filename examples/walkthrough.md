## 1. 轻档：修 CLI 参数解析 bug

**对齐**：`--config` 缺少参数时当前会静默使用默认值，用户以为配置已加载。验收例子：

1. `--config` 缺参数时返回码 2，并输出用法提示。
2. `--config path` 正常读取指定文件。
3. 不带 `--config` 时保持原默认行为。

需求明确，未使用 grilling。

**拆分**：单任务。参数解析、错误信息和测试同属一个可独立交付的 CLI 修复。

**分档**：轻档。不涉及外部写、权限、数据迁移、对外契约、跨模块或交接。

**分支**：`fix/<tool>/t-18-config-arg`，从 `develop` 创建。

**计划与根因检查**：不建任务文件；先复现，再确定修复点。

- 根因依据：`app --config` 的失败用例显示缺参分支落入默认值 → 参数解析器未区分“未提供选项”和“提供选项但缺少值” → 在解析分支返回用法错误。
- 回归测试：先新增缺参测试并确认修复前失败，再实现修复并确认测试通过；同时保留正常路径和默认行为测试。

## 2. 完整档：接入新的外部邮件 API

**对齐**：新增外部邮件发送能力，涉及真实外部写、凭据、对外契约和跨模块。验收例子：

1. 使用测试账号发送一封邮件，外部写调用数为 1。
2. 凭据缺失时返回明确错误，不发起外部写。
3. 外部超时后不自动重试，保留结果未知状态和证据。
4. 重复执行同一请求不产生第二封邮件。
5. 现有 CLI 行为不变。

需求涉及外部写和凭据，先用 grilling 澄清了幂等、超时和测试账号边界。

**拆分**：单任务。适配器、凭据、幂等和错误分类共享同一对外契约，拆分会产生不可交付中间态。

**分档**：完整档。命中外部写、权限/凭据、对外契约、跨模块。

**分支**：`feat/<tool>/t-19-mail-api`，从 `develop` 创建；worktree 位于 `../<repo>-wt/t-19-mail-api/`。

**计划**（任务文件 `tasks/2026-10-22-t-19-mail-api.md`）：

- 步骤：适配器接口 → 凭据读取 → 幂等键 → 错误分类 → 集成测试。
- 风险：真实外部写不可回滚；超时结果未知。
- 第一性原理检查：目标是可靠地执行一次邮件发送；不可变约束是真实写不可回滚、超时结果可能未知；关键假设是提供方支持幂等键；由此推导为单次调用、写前校验、持久化幂等键，不引入自动重试。
- 对抗性审查：如果先写后校验，重复执行会产生第二封邮件；改为幂等键前置检查。
- 奥卡姆检查：不引入消息队列和重试框架，单次调用加幂等键足够。

## 3. 拆分：一轮需求拆成多个任务

**对齐**：一轮需求包含三项能力：列表项高亮样式调整、批量删除、自定义分类。验收例子按能力分组，共 8 条。

**拆分判定**：

| 候选能力 | 独立结果或契约 | 失败/回滚边界 | 中间态可交付 | 共享契约/交互 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 高亮样式调整 | 列表项渲染结果 | 无外部写 | 是 | 与取消旧样式同一视觉规则 | 合并为 T-21 |
| 批量删除 | 删除 API 与列表交互 | 部分成功、恢复记录、结果未知 | 是 | 无 | 独立为 T-22 |
| 自定义分类 | 分类数据模型、编辑筛选、导入契约 | 导入失败可回滚 | 是 | 无 | 独立为 T-23 |

**任务与依赖**：T-21（样式，完整档，负责共享的 `SPEC.md`/`CHANGELOG.md` 变更）；T-22（批量删除，完整档，依赖 T-21 的列表组件改动）；T-23（自定义分类，完整档，依赖 T-21）。

**并行判定**：T-22 和 T-23 都改列表页与筛选组件，触碰范围重叠，按 T-21 → T-22 → T-23 串行；若两者触碰范围不重叠且无共享未合入契约，则默认并行。

**交付**：三个任务各建任务文件、分别提交、分别写证据；`TASK.md` 三行，依赖列写 T-22/T-23 → T-21；T-22 → T-23 的串行顺序记在 `.plan/`。
