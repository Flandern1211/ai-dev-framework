本文件仅展示实例；权威关系见 [AGENTS.md 第 1.1 节](../AGENTS.md#11-文件权威)。

## 1. 轻档 Bug：CLI 缺少参数

场景：`--config` 缺少值时误用默认配置。

验收：

1. `app --config` 返回码 2 并输出用法。
2. `app --config path` 读取指定文件。
3. `app` 保持默认行为。

根因：失败用例显示缺参分支落入默认值 → 解析器未区分“未提供选项”和“选项缺值” → 缺值分支返回用法错误。

记录：轻档；单任务；证据写提交正文。

```text
go test ./cmd/...        # pass
app --config             # exit 2
app --config ./a.yaml    # 指定配置
app                      # 默认配置
```

非阻塞缺口：Windows 路径大小写。动作：在 Windows 运行对应回归测试；通过后关闭。

```text
fix(T-18): 修复 --config 缺参数时的解析错误

AC: AC-12
Tested: go test ./cmd/... (pass); app --config (exit 2)
Env: local
Writes: 0
Unverified: Windows 路径大小写（非阻塞）；动作：运行 Windows 回归测试；关闭条件：通过
```

## 2. 完整档：外部邮件 API

场景：新增邮件发送，涉及真实外部写、凭据、公共契约和多个模块。

验收：

1. 测试账号发送一封邮件，写调用数为 1。
2. 凭据缺失时不发起外部写。
3. 超时后保留结果未知，不自动重试。
4. 重复请求不产生第二封邮件。
5. 现有 CLI 行为不变。

分档：完整档。任务文件为 `tasks/2026-10-22-t-19-mail-api.md`。

计划：适配器 → 凭据读取 → 幂等键 → 错误分类 → 集成测试。补充审查结论：单次调用和写前幂等校验足够，不引入消息队列或重试框架。

| 层级 | AC | 步骤 | 环境 | 结果 | 🔴 未验证 |
| --- | --- | --- | --- | --- | --- |
| 单元 | AC-02/03/04 | `go test ./mail/...` | 本地 Mock | 通过 | 无 |
| 真实集成 | AC-01 | `go run ./cmd send --to <test-address>` | 测试账号 | 1 次写入并收到 | 生产域名 |
| 人工验收 | AC-05 | CLI smoke test | 本地 | 行为不变 | 无 |

生产域名验收缺少测试账号，阻塞发布；测试账号结果不受影响。关闭动作：使用生产测试账号发送一封并确认收件，记录写次数和结果。

## 3. 一轮需求拆成三个任务

场景：列表高亮、批量删除、自定义分类。

| 能力 | 独立验收 | 回滚边界 | 共享项 | 结论 |
| --- | --- | --- | --- | --- |
| 高亮 | 视觉回归 | 无外部写 | 列表渲染 | T-21 |
| 批量删除 | 部分成功与恢复 | 删除 API | 列表页 | T-22 |
| 自定义分类 | 设置、清除、导入 | 导入回滚 | 筛选组件 | T-23 |

三项都修改列表或筛选组件，按 T-21 → T-22 → T-23 串行。每个任务独立记录 AC 和证据。

## 4. 重大决定只暂停相关范围

场景：本地索引与托管搜索都会改变架构、费用和数据边界，SPEC 尚未决定。

调查结果：本地索引满足离线要求；托管方案的持续费用和数据驻留未知。

决策包：

- 选项：本地索引增加客户端体积；托管搜索增加外部依赖和费用。
- 建议：确认数据驻留与预算前优先本地索引。
- 暂停：搜索存储适配器和部署设计。
- 恢复：开发者确认路线，或新约束使答案唯一。

CLI 参数修复与该决定无依赖，继续实施；搜索任务记录为 `进行中（待决定）`。

## 5. 轻档设计验证：性能结论不足

命题：低配目标设备能否在 300 ms 内查询 10 万条记录。

预声明：

- 两批各 30 次代表性查询；两批 P95 ≤ 300 ms 为支持，两批 > 300 ms 为否定，跨阈值为结论不足。
- 适用范围：仅用于当前搜索选型。
- 影响：搜索索引适配器及依赖该性能结论的任务。
- 预算：半天；达到判据或时限即停止。
- 代码：实验后删除；需要复现时转为受检查的基准测试。

结果：两批 P95 为 280 ms 和 330 ms，结论不足；搜索架构仍待决定。

## 6. 运行责任与部署

### 纯库

采用 `独立开发 + 不运行`。SPEC 记录不运行及原因，不创建 RUNBOOK。

### 首次持续运行

Agent 调查环境、公开访问、账号、费用、数据、恢复和监控，开发者确认运行责任。SPEC 记录运行设计并链接已有 `OPERATIONS.md`；不创建第二份手册。

### 已有流水线

实例：流水线 `release.yml`，目标 `staging`，版本 `v1.4.0`，检查点为 job → `/health` → smoke test。开发者授权 Agent 触发预发；生产发布保留平台人工审批门。流水线失败后停止并保留运行记录。
